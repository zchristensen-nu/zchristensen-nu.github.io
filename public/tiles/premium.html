02Process

How I build

Good tools disappear. They shorten the distance between an idea and the *feedback* it needs, then get out of the way. Everything here is built to that standard, and written up *honestly*.

010203/ 03

Principle 01

Prototype in the real medium

Mockups lie about latency, overflow and touch. I get to a running thing on day one and review it where it will actually live.

Principle 02

Shorten the feedback loop

Every tool I build narrows the gap between noticing something and fixing it. Comments belong on the page, not buried in a thread.

Principle 03

Budget for the last ten percent

Easing, focus states and empty states are where trust is earned. They get planned up front, not squeezed in at the end.

// Semi-implicit Euler spring, used for the cursor and previews
export function spring(to: number, k = 170, c = 26) {
  let x = 0, v = 0;
  return (dt: number) => {
    v += (-k * (x - to) - c * v) * dt;
    x += v * dt;
    return x;
  };
}
